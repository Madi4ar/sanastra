# Sanastra — LMS: лендинг, панель суперадминистратора и кабинеты организаций

Фронтенд по ТЗ `../frontend_superadmin_spec.md`.

**Стек:** React 19 + TypeScript strict, Vite, Ant Design 6 (ru_RU, тема через `ConfigProvider`), lucide-react, TailwindCSS 4 (только layout/утилиты, без preflight), TanStack Query, React Router, React Hook Form + Zod, Day.js, Vitest + RTL, Playwright.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
```

Бэкенда пока нет, поэтому API обслуживает **мок-сервер MSW** (`src/mocks`) — настоящие HTTP-запросы к `/api/...`, контракты как в разделе 11 ТЗ. Состояние мок-БД хранится в `localStorage`, поэтому изменения видны после перезагрузки и в соседних вкладках.
Чтобы работать с реальным API, запустите приложение с `VITE_USE_MOCKS=false`.

**Вход** (`/login`) — двухэтапный по ИИН (ТЗ «Регистрация, авторизация и ролевая модель»): ИИН → «Далее» → пароль → «Войти». Регистрация — `/register`. Демо-учётные записи (пароль `Sanastra1`):

## Регистрация, авторизация и роли

- **Регистрация:** ИИН (12 цифр + контрольный разряд ИИН РК), фамилия, имя, отчество (необязательно), область (справочник регионов РК с API), телефон с маской `+7 (XXX) XXX-XX-XX` (формат `+7 7XX XXX XX XX`), email, пароль (≥ 8 символов, цифра и заглавная буква). Уникальность ИИН и email проверяет сервер. Новому пользователю присваивается роль «Слушатель», после регистрации — профиль в личном кабинете.
- **Вход:** если ИИН не найден — «Пользователь с таким ИИН не найден. Пожалуйста, зарегистрируйтесь» и кнопка регистрации. После 5 неверных паролей подряд аккаунт блокируется на 15 минут. Если организация заблокирована или подписка истекла, вход с ролями этой организации блокируется на этапе авторизации.
- **Маршрутизация:** Слушатель → `/learn`, Тренер → `/trainer`, Админ организации → `/{client_slug}/admin`, Суперадминистратор → `/superadmin`. При нескольких ролях — кабинет с наивысшими правами (Суперадмин > Админ клиента > Тренер > Слушатель) и смена роли в шапке профиля.
- **Назначение ролей:** Суперадминистратор (раздел «Пользователи» в левом меню — все пользователи платформы; кнопка «Назначить роль» в строке пользователя рядом с «Редактировать», роль назначается с выбором организации) или Администратор клиента (модуль «Пользователи») назначает зарегистрированному пользователю роль Администратор или Тренер по ИИН. Роль Superadmin назначается записью в БД при развёртывании.
- **Суперадмин, левое меню:** «Организации», «Тарифные планы», «Пользователи». Использование лимитов каждой организации показано внизу её карточки (блок «Использование ресурсов»: использовано / осталось).
- **Пользователи (суперадмин):** создание (поля как при регистрации, роль «Слушатель»), редактирование данных и пароля, снятие ролей, удаление с подтверждением. Удалить себя или снять с себя роль суперадминистратора нельзя.
- В мок-сервере пароль хранится упрощённым хэшем; реальный бэкенд — Argon2/bcrypt и шифрование ИИН.

Сессия хранится отдельно для каждой вкладки (`sessionStorage`), а мок-БД общая (`localStorage`). Поэтому можно открыть панель суперадмина в одной вкладке, кабинет организации — в другой и смотреть, как изменения применяются в реальном времени.

Dev-утилиты в консоли браузера:

```js
window.__mock.simulatePayment('academy') // имитация онлайн-оплаты (SYSTEM_PAYMENT, version+1)
window.__mock.setSseDisabled(true)       // имитация недоступности SSE (включится polling)
window.__mock.reset()                    // сброс мок-БД
```

## Как закрыты ключевые требования

- **Реестр:** поиск с debounce 400 мс, фильтры по статусу и тарифу, серверная пагинация 10/20/50/100 — всё синхронизировано с URL; skeleton при первой загрузке, `keepPreviousData` при обновлении, состояния error / empty / no results, «Повторить».
- **Карточка:** default / override / effective для модулей визуально различаются (контурный тег / синий тег «Индивидуально» / заливка итогового значения); `Включён / Отключён` (выбор значения, равного тарифу, снимает индивидуальную настройку). Лимиты зафиксированы в тарифе и показаны только для чтения — меняются переходом на другой тариф.
- **Смена тарифа:** конфигурация нового тарифа загружается с API, в модалке — сравнение «сейчас / после смены», предупреждение об индивидуальных настройках и выбор политики (`KEEP_COMPATIBLE` / `RESET` — список приходит с сервера). Применяется только после общего «Сохранить».
- **Сохранение:** закреплённая панель, индикатор изменений, блокировка повторной отправки, подтверждение критических изменений (тариф, отключение подписки, прошедшая дата, отключение модулей, уменьшение лимитов), `fieldErrors` → поля, 409 → «Загрузить актуальные данные», 5xx → уведомление с «Повторить» без потери данных, подтверждение ухода со страницы с несохранёнными изменениями.
- **Внешние изменения (оплата):** refetch при фокусе вкладки и каждые 30 с; чистая форма обновляется автоматически, при несохранённых правках показывается предупреждение — устаревшая форма не сохранится поверх (сервер вернёт 409 по `version`).
- **Блокировка:** при `BLOCKED` / `EXPIRED` (статус вычисляет сервер) — переход на `/:clientSlug/subscription-blocked`.

## Кабинет организации и личный кабинет (разделы 18–31)

- **Маршруты** (от базового пути роли — `/learn`, `/trainer`, `/:clientSlug/admin`): главная, `organization`, `organization/subscription`, `organization/modules`, `organization/usage`, `profile`, `subscription-blocked`, `feature-unavailable`; модули — `m/:moduleCode`.
- **Права:** функция доступна только при праве роли **и** включённом модуле организации (`canUseFeature`). Обычный пользователь не видит тариф, overrides и технические коды. Раздел «Организация» доступен только администратору.
- **Навигация:** пока не получена access-конфигурация, показывается skeleton меню, поэтому запрещённые пункты не мелькают. На desktop — sidebar, на небольших экранах — Drawer. В шапке: поиск по доступным разделам, уведомления, профиль.
- **Real-time:** одно SSE-соединение `/api/tenant/events` на вкладку, закрывается при выходе. События объединяются (debounce 300 мс), показывается один toast «Настройки подписки обновлены», изменившиеся значения подсвечиваются. Блокировка и отключение модуля применяются немедленно: служебная страница или переход на dashboard с уведомлением, без повтора запрещённого запроса.
- **Устойчивость:** reconnect с экспоненциальным backoff, после восстановления — полный refetch. Если SSE недоступен дольше 10 с, включается polling раз в 30 с. При возврате во вкладку всегда сверяется `configVersion`.
- **Лимиты:** использование приходит с сервера, на клиенте не вычисляется. Пороги: до 80 % — норма, 80–94 % — warning, от 95 % — error. Если лимит исчерпан, создание блокирует и сервер (`403 LIMIT_REACHED`), и интерфейс. Если лимит уменьшен ниже текущего использования, показывается Alert, данные сохраняются.
- **Design tokens:** один источник в `src/app/theme.ts` для Ant Design и Tailwind (CSS-переменные). Стандартная палитра Tailwind отключена, поэтому цветов вне токенов нет. Радиусы 8 и 12 px, высота контролов 40 px, сетка 8 px, отступы страницы 24/16 px.

## Тарифные планы, подписка и история (ТЗ «Управление тарифными планами…»)

- **Конструктор тарифов** (`/superadmin/tariffs`): список тарифов (годовая цена, лимиты, число модулей и организаций), «Создать новый тариф» и редактирование. Поля: название, системный код (slug), годовая цена (KZT/год), лимиты `USERS_COUNT` (1–10 000), `COURSES_COUNT` (1–1 000), `STORAGE_GB` (0,5–2 000), переключатели ON/OFF для всех модулей (системный модуль всегда включён). Справочник `tariff_plans` хранится в мок-БД.
- **Карточка организации → «Управление текущей подпиской»:** выбор тарифа, автоподстановка базовой годовой цены, ручная скидка в KZT или %, итог `max(0, базовая цена − скидка)`, «Продлить подписку (+1 год)» или точная дата окончания.
- **Условия периода фиксируются:** цена и лимиты копируются из тарифа при оформлении, смене тарифа и продлении. Изменение шаблона тарифа не меняет уже оформленные периоды и историю.
- **Временные модули:** модуль вне тарифа можно включить со сроком действия (дата и время). Фоновый «cron worker» мок-сервера (раз в 5 с и перед каждым запросом) переводит такие модули в OFF при наступлении срока и публикует событие для кабинетов (источник «планировщик»).
- **«История тарифов и периодов подписки»** внизу карточки: дата операции (активация / продление / смена тарифа / изменение условий), тариф, период, базовая цена, скидка, итоговая цена, статус. Запись создаётся сервером при каждом сохранении условий подписки и при онлайн-оплате (`simulatePayment`). Активна всегда одна запись, остальные — «Завершён».
- Сброс кэша разрешений (Redis) — задача бэкенда; клиент инвалидирует свои запросы и получает SSE-событие.

## Реестр модулей (ТЗ «Реестр модулей и версионирование функционала»)

- Раздел меню **«Модули»** (`/superadmin/modules`): древовидная таблица модулей → опций → вложенных опций, текущая версия с историей версий, поиск по названию/ключу, «Развернуть/Свернуть все».
- Суперадминистратор только **переименовывает** отображаемые названия (модулей и опций) или возвращает системное. Удаления и включения/выключения в реестре нет.
- Модули публикует разработка через системный API `POST /api/system/module-registry` (`key`, `systemName`, `version` в формате semver, дерево `options`). Перечень опций заменяется целиком, коммерческие названия сохраняются по ключам, понижение версии → 409. В dev: `window.__mock.publishModule({...})`.
- Наполнение — перечень первой очереди из раздела 4 ТЗ, кроме «Элементы контента (Конструктор курсов)» — отложено. `lms_prog_core` оставлен без коммерческого названия как пример из ТЗ.

## Создание организации

В реестре суперадмина есть кнопка «Создать организацию». Поля: название, адрес кабинета `client_slug` (генерируется из названия с транслитерацией русских и казахских букв, уникальность проверяется на сервере, зарезервированные адреса запрещены), тариф, подписка и даты. Модули и лимиты наследуются от тарифа. После создания открывается карточка организации.

**Редактирование и удаление организации:** кнопка «Удалить» в шапке карточки удаляет организацию после ввода её адреса кабинета (вместе с подпиской, историей, контентом и ролями пользователей в ней; учётные записи остаются). Кнопка «Редактировать» меняет название и адрес кабинета `client_slug` (уникальность проверяется на сервере, роли пользователей переносятся на новый адрес). Тариф, подписка и даты меняются в блоке «Управление текущей подпиской». Блок «Лимиты» в карточке временно скрыт (флаг `SHOW_LIMITS_SECTION` в `OrganizationEditor.tsx`).

## Мок-данные курсов и вебинаров

- **Курсы** (`/academy/m/COURSES`): каталог с категориями, преподавателем, числом уроков и учеников, средним прогрессом и статусом (опубликован / черновик); KPI, фильтр по статусу и категории, поиск. Новый курс создаётся черновиком; использование лимита «Количество курсов» сервер считает по фактическому числу курсов.
- **Вебинары** (`/academy/m/WEBINARS`): «Сейчас в эфире», «Предстоящие» с записью и отменой записи (с учётом мест), «Записи». Статус (эфир / предстоит / запись) сервер вычисляет по времени. Время мок-данных отсчитывается от момента первого открытия.
- Создавать курсы может только администратор организации (право `courses.manage`); обычный пользователь курсы только просматривает. Сервер проверяет это независимо.
- Контент хранится в `localStorage` (`src/mocks/content.ts`) и сбрасывается вместе с мок-БД.

## Визуальный язык

Кабинет организации и личный кабинет сверстаны по образцу прототипа **NIS Academy** (github.com/Madi4ar/nis-academy) и перенесены на Ant Design + Tailwind:

- палитра indigo `#4f46e5` + sky `#0ea5e9` с мягкими подложками статусов, шрифт Inter;
- белый sidebar 248 px с градиентным логотипом и подписью роли, шапка с blur, кнопка профиля с ролью;
- администратор организации: заголовок 28 px, ряд KPI-карточек (`StatCard`), сетка «быстрые действия + лимиты»;
- пользователь: градиентная приветственная карточка и сетка «Мои разделы».

Это единая система токенов, поэтому панель суперадмина тоже использует новую палитру.

## Допущения (вопросы из раздела 17 ТЗ)

Пока нет ответов, в мок-сервере приняты такие допущения — их легко поменять:

- Каталог: 7 модулей (`USERS` — системный, его нельзя переопределить), 3 лимита; параметры тарифов «Базовый / Стандарт / Бизнес» (100 000 / 200 000 / 300 000 ₸ в год, как на лендинге) заданы условно.
- В историю попадает изменение тарифа, дат или скидки; изменение только модулей запись не создаёт. Онлайн-оплата сохраняет персональную скидку клиента.
- Дата окончания включительна; дата начала в будущем → статус `BLOCKED`.
- Панель суперадмина отслеживает внешние изменения через refetch и polling, кабинет организации — через SSE.
- Права ролей (`courses.view`, `organization.manage` и т.д.) и порог предупреждения об окончании подписки (14 дней) заданы условно.
- Цвета бренда — заглушки в `src/app/theme.ts`.
